AOGIMI WEB FRONTEND — BACKEND CONNECTION INVENTORY
=====================================================
Last reviewed: 2026-05-20

Base URL: NEXT_PUBLIC_API_URL (default: http://localhost:3000)
HTTP helpers live in lib/api.ts (apiUrl, apiGet, apiSend, apiSendVoid).
Both apiSend and apiSendVoid accept an optional AbortSignal.
Domain types live in lib/types/{book,deck,dict,user,device,translate}.ts.


==============================================================================
1. AUTHENTICATION
   File: components/providers/AuthProvider.tsx, lib/auth/authApi.ts, lib/api.ts
==============================================================================

Token model: "memory + httpOnly cookie" (web). The backend returns the
access token in the JSON body and sets the refresh token as an httpOnly +
Secure + SameSite=Lax cookie scoped to /api/auth. All auth calls use
credentials:'include'. Native clients (no Origin header) get the refresh
token in the body instead. See ../../docs/AUTH.md.

POST /api/auth/login
  Trigger:   User login (manual)
  Request:   { username, password }
  Response:  { user: UserProfile, accessToken }   (+ Set-Cookie: refresh)

POST /api/auth/register
  Trigger:   User signup (manual) -- CURRENTLY DISABLED server-side (403)
  Request:   { username, password }
  Response:  { user: UserProfile, accessToken }   (+ Set-Cookie: refresh)

POST /api/auth/refresh
  Trigger:   401 refresh-retry (lib/api.ts) + silent session-restore on boot
  Request:   (no body — refresh token rides in the httpOnly cookie)
  Response:  { user, accessToken }                (+ rotated Set-Cookie)
  Notes:     Browser requests are rejected 403 if Origin is not allowlisted
             (CSRF guard). On 401/403 the cookie is cleared server-side.

POST /api/auth/logout
  Trigger:   Manual logout
  Request:   (no body — cookie carries the token)
  Response:  { ok: true }                         (+ cookie cleared)

3. BOOKS / EPUB
   File: lib/booksApi.ts
==============================================================================

POST /api/books
  Trigger:   New EPUB import (manual, once per book)
  Request:   { userId, filename, title, author, coverColor,
               fileHash?, contentHash?, dcIdentifier?, language?, publisher? }
  Response:  BookProgressRecord

GET /api/books/user/{userId}
  Trigger:   Library mount, reader mount, profile mount (once per page load)
  Response:  BookProgressRecord[]

GET /api/books/{id}
  Trigger:   Single book fetch (on demand)
  Response:  BookProgressRecord

PUT /api/books/{id}/progress
  Trigger:   Reader page turn / chapter change
  Frequency: Debounced — first fire immediate, subsequent ~2s
  Request:   ProgressPayload  -- { cfiPosition?, progress?, spineIndex?, totalSpineItems? }
  Response:  BookProgressRecord

PUT /api/books/{id}/progress  (sendBeacon path)
  Trigger:   Page unload / tab close — fire-and-forget via sendProgressBeacon()
  Notes:     Browser guarantees delivery even if the tab dies. No response read.

PATCH /api/books/{id}
  Trigger:   In-place book title rename (manual)
  Request:   { title }
  Response:  BookProgressRecord

DELETE /api/books/{id}
  Trigger:   Book deletion (manual)
  Response:  void

POST /api/books/match
  Trigger:   Library restore — given a list of local files, ask the backend
             which match existing user books by file_hash → xmp_original_id
             → pdf_id_original → detected_doi → detected_isbn+page_count(±5%)
             → content_hash → visual(phash+page_count(±10%)) →
             dc_identifier+title → filename (priority order).
             EPUB candidates leave PDF-only fields null; PDFs without a text
             layer leave content_hash/doi/isbn null. Mobile always leaves
             text-derived + page_phashes null (no extractor / no renderer).
  Request:   { userId, books: MatchCandidate[] }
  Response:  (MatchResult | null)[]   parallel-indexed to the request
             match_type ∈ file_hash / xmp_original_id / pdf_trailer_id /
                          doi / isbn / content / visual / metadata / filename
             `visual` is medium confidence — NOT in STRONG_MATCH_TYPES.

PUT /api/books/{id}/identity
  Trigger:   Backfill — when a local book gains a hash that the backend
             record doesn't have yet (manual or automatic on import).
  Request:   BookIdentityPayload --
             { fileHash, contentHash, pdfIdOriginal, pdfIdCurrent,
               pageCount, hasTextLayer, producer,
               xmpDocumentId, xmpOriginalId,
               pageHashes, textLength, detectedDoi, detectedIsbn,
               pagePhashes,
               fingerprintVersion,
               dcIdentifier, language, publisher }
  Response:  BookProgressRecord

BookProgressRecord shape:
  { id (UUID), user_id, filename, title, author, cover_color,
    cfi_position, spine_index, total_spine_items, progress,
    file_hash, content_hash, pdf_id_original, pdf_id_current,
    page_count, has_text_layer, producer,
    xmp_document_id, xmp_original_id,
    page_hashes, text_length, detected_doi, detected_isbn,
    page_phashes,
    fingerprint_version,
    dc_identifier, language, publisher,
    started_at, last_read_at, created_at }

5. DICTIONARY & WORD SEARCH
   File: lib/dictApi.ts
==============================================================================

GET /api/search?q={query}
  Trigger:   Dictionary input typing (debounced via DictionaryStateProvider),
             URL-based search, kanji lookup from word detail.
  Response:  SearchResponse
    | { type: 'kanji',   kanji: KanjiInfo | null, words: WordResult[], names: NameResult[] }
    | { type: 'word',    words: WordResult[] }
    | { type: 'kana',    words: WordResult[], names: NameResult[], kanjis: KanjiInfo[] }
    | { type: 'meaning', words: WordResult[] }

GET /api/words/{id}/details
  Trigger:   Word selection from search results (manual)
  Response:  DetailsResponse  -- { word: WordResult, kanjis: KanjiInfo[] }

WordResult shape:
  { id, is_common, jlpt_level (1..5 | null), grade, char_grades[],
    kanji[], readings[], meanings[{meaning, pos, lang}] }

KanjiInfo shape:
  { literal, grade, jlpt_level (1..5 | null), stroke_count, radical,
    meanings[], on_readings[], kun_readings[] }

7. SYNC & PERSISTENCE PATTERNS
==============================================================================

Reading-progress sync:
  - Local:    Immediate save to ReaderStateProvider state (in-memory).
  - Backend:  First put immediate; subsequent puts debounced ~2s.
  - On unload: sendBeacon(PUT /api/books/{id}/progress) — fire-and-forget.
  - Failures silently swallowed (non-critical).

Library / device sync (library page mount):
  1. Load local IndexedDB records.
  2. Register the device (POST /api/devices) if absent.
  3. Fetch backend books (GET /api/books/user/{id}).
  4. Optionally fetch availability (GET /api/devices/{deviceId}/books).
  5. matchBooks() reconciles unidentified local files with existing records.
  6. Backfill identity (PUT /api/books/{id}/identity) for matched-but-stale rows.

Profile page load:
  - Fetches user info, books, decks, devices in parallel via
    Promise.allSettled(). Each can fail independently.

Client-side storage:

  localStorage (synchronous string/JSON kv) — keys + scope:

    Device-scoped (kept across account switches):
      lgc_device_id              per-browser device UUID, sent with every
                                 /api/devices call
      app-theme                  active theme name; read by the pre-hydration
                                 <script> in app/layout.tsx to avoid
                                 flash-of-default-theme
      lgc_last_user_id           the last user id that owned local data;
                                 survives logout so the next sign-in can
                                 detect an account switch (see Account
                                 switch wipe below)

    Auth tokens (NOT in localStorage anymore):
      The refresh token is an httpOnly + Secure + SameSite=Lax cookie
      (set by the backend, scoped to /api/auth) — unreadable by JS. The
      access token lives in memory only (lib/auth/tokenStore.ts) and is
      re-minted on boot by a silent POST /api/auth/refresh. The legacy
      keys aogimi_access_token / aogimi_refresh_token are purged + revoked
      on first load by the migration in AuthProvider.

    User-scoped (wiped on account switch):
      auth_user                  { id, username } cached for first-paint
                                 (replaced by the new user on sign-in,
                                 cleared on logout)
      lgc_avatar_index           profile avatar palette choice
      lgc_needs_onboarding       first-run explainer flag
      dictionary_state           sticky dictionary view state
      dictionary_recent_searches recent search history
      reader_book_<filename>     per-book highlights + bookmarks + lastCfi
                                 + per-book reader prefs (uri-encoded
                                 filename). HIGHLIGHTS LIVE ONLY HERE —
                                 there is no backend table yet.
      reader_progress_<filename> per-book progress recovery snapshot
                                 (every page turn; backend is canonical)

  IndexedDB databases:

    aogimi-books (v1) — user-scoped, wiped on account switch
      metadata store (keyPath 'id')
        Full local BookRecord per imported book: title, author, filename,
        coverColor, hasCover, coverImage (base64 data URL), fileHash,
        contentHash, dcIdentifier, language, publisher, importedAt,
        fileSize.
      files store (keyed by id)
        Raw .epub / .pdf ArrayBuffer. This is the only place the actual
        book content lives — backend stores metadata only.

    File System Access API handles (separate IDB, see lib/fsAccess.ts)
      handles store
        FileSystemDirectoryHandle the user picked as their "library
        folder". Survives sessions because IndexedDB persists
        structured-clone handles. Optional UX nicety; kept across
        account switches (it's a folder, not user data).

  In-memory caches (lost on reload, never persisted):
    Dictionary search/word results
    Books list + library reconcile state inside React tree

Account-switch wipe:
  Trigger:  AuthProvider.handleAuthenticated() compares incoming user.id
            against lgc_last_user_id (NOT auth_user — that key is cleared
            on logout and would miss the typical sign-out → sign-in flow).
            On mismatch, lib/auth/wipeUserData.ts runs before persist().
  Wipes:    Every user-scoped key listed above + the aogimi-books IDB
            (deleteDatabase + cached connection reset).
  Single book delete:
            lib/books/deleteBook.ts owns the per-book cleanup
            (backend row + IDB metadata + IDB file blob + the two
            localStorage entries). Used by the library trash button.
