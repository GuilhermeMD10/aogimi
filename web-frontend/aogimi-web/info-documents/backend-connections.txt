1. AUTHENTICATION
   File: components/providers/AuthProvider.tsx, lib/auth/authApi.ts, lib/api.ts
==============================================================================

Token model: "memory + httpOnly cookie" (web). The backend returns the
access token in the JSON body and sets the refresh token as an httpOnly +
Secure + SameSite=Lax cookie scoped to /api/auth. All auth calls use
credentials:'include'. Native clients (no Origin header) get the refresh
token in the body instead. See ../../docs/AUTH.md.

POST /api/auth/login
  Trigger:   User login (manual)
  Request:   { username, password }
  Response:  { user: UserProfile, accessToken }   (+ Set-Cookie: refresh)

POST /api/auth/register
  Trigger:   User signup (manual) -- CURRENTLY DISABLED server-side (403)
  Request:   { username, password }
  Response:  { user: UserProfile, accessToken }   (+ Set-Cookie: refresh)

POST /api/auth/refresh
  Trigger:   401 refresh-retry (lib/api.ts) + silent session-restore on boot
  Request:   (no body — refresh token rides in the httpOnly cookie)
  Response:  { user, accessToken }                (+ rotated Set-Cookie)
  Notes:     Browser requests are rejected 403 if Origin is not allowlisted
             (CSRF guard). On 401/403 the cookie is cleared server-side.

POST /api/auth/logout
  Trigger:   Manual logout
  Request:   (no body — cookie carries the token)
  Response:  { ok: true }                         (+ cookie cleared)

3. BOOKS / EPUB
   File: lib/booksApi.ts
==============================================================================

POST /api/books
  Trigger:   New EPUB import (manual, once per book)
  Request:   { userId, filename, title, author, coverColor,
               fileHash?, contentHash?, dcIdentifier?, language?, publisher? }
  Response:  BookProgressRecord

GET /api/books/user/{userId}
  Trigger:   Library mount, reader mount, profile mount (once per page load)
  Response:  BookProgressRecord[]

GET /api/books/{id}
  Trigger:   Single book fetch (on demand)
  Response:  BookProgressRecord

PUT/POST /api/books/{id}/progress
  Trigger:   EPUB reading-position sync (periodic ~60s + on exit + on
             "Back to library") and the "Mark finished" action.
  Request:   ProgressPayload  -- { cfiPosition?, progress?, spineIndex?,
             totalSpineItems? }   ("mark finished" sends { progress: 100 })
  Response:  BookProgressRecord
  Notes:     Backend COALESCEs omitted fields and bumps last_read_at. The
             exit flush uses a keepalive POST (sendProgressKeepalive) so it
             carries the Bearer token on teardown. PDF not synced yet.

PATCH /api/books/{id}
  Trigger:   In-place book title rename (manual)
  Request:   { title }
  Response:  BookProgressRecord

DELETE /api/books/{id}
  Trigger:   Book deletion (manual)
  Response:  void

POST /api/books/match
  Trigger:   Library restore — given a list of local files, ask the backend
             which match existing user books by file_hash → xmp_original_id
             → pdf_id_original → detected_doi → detected_isbn+page_count(±5%)
             → content_hash → visual(phash+page_count(±10%)) →
             dc_identifier+title → filename (priority order).
             EPUB candidates leave PDF-only fields null; PDFs without a text
             layer leave content_hash/doi/isbn null. Mobile always leaves
             text-derived + page_phashes null (no extractor / no renderer).
  Request:   { userId, books: MatchCandidate[] }
  Response:  (MatchResult | null)[]   parallel-indexed to the request
             match_type ∈ file_hash / xmp_original_id / pdf_trailer_id /
                          doi / isbn / content / visual / metadata / filename
             `visual` is medium confidence — NOT in STRONG_MATCH_TYPES.

PUT /api/books/{id}/identity
  Trigger:   Backfill — when a local book gains a hash that the backend
             record doesn't have yet (manual or automatic on import).
  Request:   BookIdentityPayload --
             { fileHash, contentHash, pdfIdOriginal, pdfIdCurrent,
               pageCount, hasTextLayer, producer,
               xmpDocumentId, xmpOriginalId,
               pageHashes, textLength, detectedDoi, detectedIsbn,
               pagePhashes,
               fingerprintVersion,
               dcIdentifier, language, publisher }
  Response:  BookProgressRecord

BookProgressRecord shape:
  { id (UUID), user_id, filename, title, author, cover_color,
    cfi_position, spine_index, total_spine_items, progress,
    file_hash, content_hash, pdf_id_original, pdf_id_current,
    page_count, has_text_layer, producer,
    xmp_document_id, xmp_original_id,
    page_hashes, text_length, detected_doi, detected_isbn,
    page_phashes,
    fingerprint_version,
    dc_identifier, language, publisher,
    started_at, last_read_at, created_at }

DeckRecord (all four deck responses share this shape)
  { id, user_id, name, description, created_at,
    card_count: number,
    last_card: { id, front, reading, back, state, created_at } | null }
  -- card_count and last_card are assembled server-side.
  -- last_card is the deck's most recently added card, null when empty. It
     feeds the decks screen's "Last Added Word" row. Do NOT fetch a deck's
     card inventory to derive it.
  -- description is still returned and is still written by the MOBILE app.
     The web dropped the feature with the decks redesign and ignores it;
     DeckSummary / Deck / DeckPatch in features/study/decks/types.ts no
     longer carry it.

POST /api/study/session
  Trigger:   Study session start / restart (useStudySession)
  Request:   { scope: 'all'|'deck', deckIds?, mode, limit?, dueOnly? }
             mode: hardest | random | oldest_first | oldest_only |
                   newest_only | by_creation | hardest_all_decks
             dueOnly: narrows the pool to due cards BEFORE mode orders it.
                      { scope:'all', dueOnly:true } = study all due cards.
  Response:  { cards: CardRecord[] }  -- already in display order, limit-capped

GET /api/study/prefs
  Trigger:   Study display prefs + deck overrides read (backend is the only
             source of truth -- no local cache)
  Response:  { display, deckOverrides }  -- defaults when no row exists

  Trigger:   Display-pref or deck-override change (manual)
  Request:   { display?, deckOverrides? }  -- either field optional (upsert)
  Response:  { display, deckOverrides }

GET /api/stats/activity
  Trigger:   /sky (study stats) mount, activity tab
  Response:  { daysStudied, perDay: [{ date:'YYYY-MM-DD', count }] }
             -- last 365 days, only days with >= 1 review

GET /api/stats/cards
  Trigger:   /sky (study stats) mount, cards tab; profile animal label
  Response:  { byState: { new, seen, learned, mastered }, total,
               hardest: CardRecord[] }  -- hardest capped at 20

GET /api/stats/recent-upgrades[?deckId={uuid}]
  Trigger:   Home "recent upgrades" row (no deckId);
             deck detail's "RECENT UPGRADES - THIS DECK" panel (with deckId)
  Helpers:   fetchRecentUpgrades(deckId?, signal) in
             features/study/stats/lib/statsApi.ts
             useDeckUpgrades(deckId) in features/study/decks/hooks/
  Response:  RecentUpgrade[] -- <=5, newest first, promotions only
  -- deckId filters BEFORE the limit. Do not fetch the global five and filter
     client-side: a deck's own promotions often aren't in the newest five
     overall, so an active deck would render as having none.
  -- 400 when deckId is present and not a uuid.

RecentUpgrade shape:                     (camelCase -- a purpose-built
  { cardId, deckId, deckName,             aggregate, not a raw cards row)
    front, reading, back,
    stateBefore, stateAfter, reviewedAt }
  -- Promotions ONLY, up the ladder new < seen < learned < mastered.
  --  again-driven demotions and same-tier reviews are excluded.
  -- Events, not distinct cards: a card promoted twice appears twice.
  -- Read from the card_reviews log, so later reviews don't overwrite it.

DeckRecord shape:
  { id, user_id, name, description, created_at, card_count }

CardRecord shape:
  { id, deck_id, front, reading, back, notes, context_sentence,
    state ('new'|'seen'|'learned'|'mastered'), reviewed_times,
    difficulty, stability, last_outcomes, last_reviewed_at,
    next_due_at, created_at }
  -- A card is "due" when next_due_at IS NULL (never reviewed) or
  --  next_due_at <= now. See docs/study-due-cards.md.

5. DICTIONARY & WORD SEARCH
   File: lib/dictApi.ts
==============================================================================

GET /api/search?q={query}
  Trigger:   Dictionary input typing (debounced via DictionaryStateProvider),
             URL-based search (?q=), kanji lookup from word detail. The home
             dictionary card's search field and its recent-lookup rows both
             route here by pushing /dictionary?q=<term> -- one search
             implementation, several doorways into it.
  Response:  SearchResponse
    | { type: 'kanji',   kanji: KanjiInfo | null, words: WordResult[], names: NameResult[] }
    | { type: 'word',    words: WordResult[] }
    | { type: 'kana',    words: WordResult[], names: NameResult[], kanjis: KanjiInfo[] }
    | { type: 'meaning', words: WordResult[] }

GET /api/words/{id}/details
  Trigger:   Selecting a row in /dictionary's results rail -- including the
             first row, which is selected automatically, and every row you
             pass through with the arrow keys. Also the reader sidekick and
             the reader bubble.
  Client:    features/dictionary/hooks/useWordDetails.ts caches per word id
             for the life of the mount and does NOT cancel in-flight requests
             when the selection moves on (they finish and warm the cache);
             everything outstanding aborts together on unmount.
  Response:  DetailsResponse  -- { word: WordResult, kanjis: KanjiInfo[],
                                   sentences: ExampleSentence[] }

WordResult shape:
  { id, is_common, jlpt_level (1..5 | null), grade, char_grades[],
    kanji[], readings[], meanings[{meaning, pos, lang}] }

KanjiInfo shape:
  { literal, grade, jlpt_level (1..5 | null), stroke_count, radical,
    meanings[], on_readings[], kun_readings[] }

7. SYNC & PERSISTENCE PATTERNS
==============================================================================

Reading-position sync (EPUB only):
  - Captured from foliate's relocate event; written to localStorage
    (reader_progress_<filename>) on every page turn (no network).
  - Flushed to book_progress (cfi_position / spine_index / progress) only
    periodically (~60s), on exit (visibilitychange:hidden / pagehide via a
    keepalive POST), and on unmount ("Back to library"). Dedup'd; the first
    relocate per open only seeds the baseline, so a restore never writes back.
  - On open, the restore anchor is the newer of the localStorage snapshot and
    the backend row (newer-wins). "Mark finished" still sends { progress: 100 }
    and sticks until the user moves. PDF not synced yet (no backend column).

Library / device sync (library page mount):
  1. Load local IndexedDB records.
  2. Register the device (POST /api/devices) if absent.
  3. Fetch backend books (GET /api/books/user/{id}).
  4. Optionally fetch availability (GET /api/devices/{deviceId}/books).
  5. matchBooks() reconciles unidentified local files with existing records.
  6. Backfill identity (PUT /api/books/{id}/identity) for matched-but-stale rows.

Profile page load:
  - Fetches user info, books, decks, devices in parallel via
    Promise.allSettled(). Each can fail independently.

Client-side storage:

  localStorage (synchronous string/JSON kv) — keys + scope:

    Device-scoped (kept across account switches):
      lgc_device_id              per-browser device UUID, sent with every
                                 /api/devices call
      lgc_last_user_id           the last user id that owned local data;
                                 survives logout so the next sign-in can
                                 detect an account switch (see Account
                                 switch wipe below)

    Auth tokens (NOT in localStorage anymore):
      The refresh token is an httpOnly + Secure + SameSite=Lax cookie
      (set by the backend, scoped to /api/auth) — unreadable by JS. The
      access token lives in memory only (lib/auth/tokenStore.ts) and is
      re-minted on boot by a silent POST /api/auth/refresh. The legacy
      keys aogimi_access_token / aogimi_refresh_token are purged + revoked
      on first load by the migration in AuthProvider.

    User-scoped (wiped on account switch):
      auth_user                  { id, username } cached for first-paint
                                 (replaced by the new user on sign-in,
                                 cleared on logout)
      dictionary_recent_searches recent search history ({ query, at })
                                 The former dictionary_state key (query +
                                 result + selected word) was removed: the
                                 /dictionary URL holds the query and the
                                 selected row now, and a second copy in
                                 localStorage drifted out of sync. Still
                                 wiped on account switch so old ones go.

    Device-scoped (NOT wiped on account switch):
      aogimi-theme               'light' | 'dark'. Written by ThemeProvider,
                                 read by the pre-paint <script> in
                                 app/layout.tsx before first paint. Falls back
                                 to prefers-color-scheme when absent.
                                 Supersedes the removed `app-theme` key; moves
                                 to a users.theme column later.

    REMOVED localStorage keys (no longer written/read):
      app-theme                  superseded by `aogimi-theme` above (the
                                 redesign reintroduced a real theme switch, so
                                 the choice has to survive a reload)
      lgc_avatar_index           avatar now read from backend (avatar_index
                                 on UserProfile) — single source of truth
      lgc_needs_onboarding       gate now reads users.onboarding_completed
                                 (GET /api/user/{id})
      study_display_prefs_v1     study display prefs now backend-backed
      study_deck_overrides_v1    deck overrides now backend-backed
      reader_book_<filename>     highlights + bookmarks + per-book reader
                                 prefs removed; reader typography prefs are
                                 in-memory only (reset each book open)
      reader_progress_<filename> EPUB reading-position buffer (cfi, spine
                                 index, percent, updatedAt); flushed to the
                                 backend periodically + on exit

  IndexedDB — single database `aogimi`
  (sole connection factory: components/books/utils/booksDb.ts):

    The old `aogimi-books` and `aogimi-fs` databases were MERGED into one
    `aogimi` DB. A one-time, idempotent copy-then-delete migration runs on
    first open and preserves imported book blobs + the directory handle.

    metadata store (keyPath 'id') — user-scoped, wiped on account switch
      Full local BookRecord per imported book: title, author, filename,
      coverColor, hasCover, coverImage (base64 data URL), fileHash,
      contentHash, dcIdentifier, language, publisher, importedAt,
      fileSize.
    files store (blobs, out-of-line key) — user-scoped, wiped on account switch
      Raw .epub / .pdf ArrayBuffer. This is the only place the actual
      book content lives — backend stores metadata only.
    handles store (out-of-line key, see lib/fsAccess.ts)
      FileSystemDirectoryHandle the user picked as their "library
      folder". Survives sessions because IndexedDB persists
      structured-clone handles. Optional UX nicety; kept across
      account switches (it's a folder, not user data) — only metadata +
      files are cleared on wipe.

  In-memory caches (lost on reload, never persisted):
    Dictionary search/word results
    Books list + library reconcile state inside React tree

Account-switch wipe:
  Trigger:  AuthProvider.handleAuthenticated() compares incoming user.id
            against lgc_last_user_id (NOT auth_user — that key is cleared
            on logout and would miss the typical sign-out → sign-in flow).
            On mismatch, lib/auth/wipeUserData.ts runs before persist().
  Wipes:    dictionary_state (legacy, no longer written) +
            dictionary_recent_searches, plus the `aogimi`
            IDB `metadata` + `files` stores (the `handles` directory handle
            is kept — it's a folder, not user data). See
            lib/auth/wipeUserData.ts.
  Single book delete:
            components/books/utils/deleteBook.ts owns the per-book cleanup
            (backend book_progress row + IDB metadata + IDB file blob). No
            longer touches localStorage (the per-book reader_book /
            reader_progress entries were removed). Used by the library
            trash button.
