3. BOOKS / EPUB
   File: lib/booksApi.ts
==============================================================================

POST /api/books
  Trigger:   New EPUB import (manual, once per book)
  Request:   { userId, filename, title, author, coverColor,
               fileHash?, contentHash?, dcIdentifier?, language?, publisher? }
  Response:  BookProgressRecord

GET /api/books/user/{userId}
  Trigger:   Library mount, reader mount, profile mount (once per page load)
  Response:  BookProgressRecord[]

GET /api/books/{id}
  Trigger:   Single book fetch (on demand)
  Response:  BookProgressRecord

PUT /api/books/{id}/progress
  Trigger:   Reader page turn / chapter change
  Frequency: Debounced — first fire immediate, subsequent ~2s
  Request:   ProgressPayload  -- { cfiPosition?, progress?, spineIndex?, totalSpineItems? }
  Response:  BookProgressRecord

PUT /api/books/{id}/progress  (sendBeacon path)
  Trigger:   Page unload / tab close — fire-and-forget via sendProgressBeacon()
  Notes:     Browser guarantees delivery even if the tab dies. No response read.

PATCH /api/books/{id}
  Trigger:   In-place book title rename (manual)
  Request:   { title }
  Response:  BookProgressRecord

DELETE /api/books/{id}
  Trigger:   Book deletion (manual)
  Response:  void

POST /api/books/match
  Trigger:   Library restore — given a list of local files, ask the backend
             which match existing user books by file_hash → content_hash →
             dc_identifier+title → filename (in priority order).
  Request:   { userId, books: MatchCandidate[] }
  Response:  (MatchResult | null)[]   parallel-indexed to the request

PUT /api/books/{id}/identity
  Trigger:   Backfill — when a local book gains a content/file hash that the
             backend record doesn't have yet (manual or automatic on import).
  Request:   EpubIdentity  -- { fileHash, contentHash, dcIdentifier, language, publisher }
  Response:  BookProgressRecord

BookProgressRecord shape:
  { id (UUID), user_id, filename, title, author, cover_color,
    cfi_position, spine_index, total_spine_items, progress,
    file_hash, content_hash, dc_identifier, language, publisher,
    started_at, last_read_at, created_at }

8. SYNC & PERSISTENCE PATTERNS
==============================================================================

Reading-progress sync:
  - Local:    Immediate save to ReaderStateProvider state (in-memory).
  - Backend:  First put immediate; subsequent puts debounced ~2s.
  - On unload: sendBeacon(PUT /api/books/{id}/progress) — fire-and-forget.
  - Failures silently swallowed (non-critical).

Library / device sync (library page mount):
  1. Load local IndexedDB records.
  2. Register the device (POST /api/devices) if absent.
  3. Fetch backend books (GET /api/books/user/{id}).
  4. Optionally fetch availability (GET /api/devices/{deviceId}/books).
  5. matchBooks() reconciles unidentified local files with existing records.
  6. Backfill identity (PUT /api/books/{id}/identity) for matched-but-stale rows.

Profile page load:
  - Fetches user info, books, decks, devices in parallel via
    Promise.allSettled(). Each can fail independently.

Client-side storage:
  - localStorage:
      auth-user                  current user
      app-theme                  theme name (read by pre-hydration script)
      reader_progress_<file>     per-book progress snapshot (one key per filename)
      lgc_avatar_index           profile avatar choice
      onboarding-state           first-run explainer dismissal
      device-id                  per-browser device UUID
      dictionary-state           recent searches + filter prefs
  - IndexedDB (langeco-books):
      metadata store             local book metadata
      files store                EPUB/PDF blobs
