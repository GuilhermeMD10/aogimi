# API reference

41 endpoints across 8 routers, plus `GET /healthz`. Generated by reading
`backend/src/routes/*.js`. Payload shapes and quota tables are in
[`backend/API_ROUTES.md`](../backend/API_ROUTES.md); this file is the flat index.

## Conventions

**Auth.** Public routers are mounted before `authenticateJWT`; protected ones after. A protected
request needs `Authorization: Bearer <accessToken>`. `req.user = { userId, username }` is the
only identity source — a `userId` in a body, query or path is ignored, and where one appears in
a path it is cross-checked against the token.

**Ownership.** Every protected route taking a resource `:id` verifies ownership via
`services/ownership.js` before doing work, and returns **404** on mismatch so "not yours" is
indistinguishable from "doesn't exist". A malformed UUID (Postgres `22P02`) also returns 404,
so a bad ID cannot be distinguished from an unknown one.

**Errors.** JSON `{ error }`. Quota violations are **409** with `{ error, code, limit, current }`.
Validation failures are 400. Rate limits are 429 with `RateLimit-*` headers (draft-7). Nothing
returns a stack trace.

**Rate limits.** 100 req/min globally on `/api`. Login is 10 per hour keyed by IP+username;
register is 10 per hour keyed by IP.

## Public

### Health

| Method | Path | Purpose |
|---|---|---|
| GET | `/healthz` | Liveness probe. Mounted before the HTTPS redirect and the rate limiter so platform healthchecks over plain HTTP inside the private network are not answered with a 308. |

### Auth — `/api/auth`

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/auth/register` | **Currently returns 403.** Handler body is intact behind an early `return`. Takes `{ username, email, password }`; 409 on `USERNAME_TAKEN` / `EMAIL_TAKEN`. |
| POST | `/api/auth/login` | `{ username, password }` → user + access token. Refresh token by cookie (browser) or body (native). 401 on bad credentials. |
| POST | `/api/auth/refresh` | Rotates the refresh token, mints a new access token. Reads the token from cookie or body. Browser requests must carry an allowlisted `Origin` (CSRF guard) or get 403. Clears a stale cookie on 401. |
| POST | `/api/auth/logout` | Revokes the supplied refresh token and clears the cookie. Tolerates a missing or invalid token — the client just needs permission to drop local state. |

### Search — `/api/search`

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/search?q=` | The unified ranked lookup. Routes by query shape (single kanji, kanji-containing word, kana, romaji/English), deinflects Japanese input, converts romaji to kana, and returns `{ type, words, … }` with kanji and name blocks where applicable. |

### Words — `/api/words`

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/words/:id/details` | Word + per-character kanji breakdown + up to 5 example sentences containing any of its forms. |

> **Removed 2026-08-17.** The `/api/kanji` (2) and `/api/names` (5) routers, ten of
> the eleven `/api/words` lookups, and the `/api/translate` DeepL proxy were deleted.
> All predated `/api/search`; none had a caller in either client. Kanji and name data
> still reach clients inline from the ranked search pipeline.

## Protected

All require `Authorization: Bearer <accessToken>`.

### User — `/api/user`

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/user/:id` | Own public profile. `requireUserMatch` rejects any `:id` that is not the token's. |
| PATCH | `/api/user` | Update `display_name`, `email`, `language`, `avatar_index`. Zod bounds every value and rejects unknown keys; the service keeps an allow-list as defence in depth so `password_hash` and `username` stay unwritable. Duplicate email → 409. |
| PUT | `/api/user/onboarding` | Mark onboarding complete. |
| DELETE | `/api/user` | Delete the account. Cascades to every user-data table and revokes all refresh tokens, so other open sessions die immediately. |

### Books — `/api/books`

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/books` | Register a book. Idempotent on (user, filename) — returns the existing row. The quota check asks "already registered?" first, so an at-quota user can still re-sync their own library from a second device. |
| POST | `/api/books/match` | Match local candidates against the caller's library via the 10-layer priority chain. Mounted before `/:id` so `match` is not captured as a book ID. Candidate array length-capped in the schema — matching is a synchronous Hamming-distance loop and an unbounded array stalls the event loop. |
| GET | `/api/books/user/:userId` | List own books. |
| GET | `/api/books/:id` | One book. |
| PUT | `/api/books/:id/progress` | Update reading position (`cfi_position`, `spine_index`, `total_spine_items`, `progress`). |
| POST | `/api/books/:id/progress` | Same handler. POST exists because the exit-path flush uses `fetch(keepalive)`. |
| PATCH | `/api/books/:id` | Update editable metadata (title). |
| PUT | `/api/books/:id/identity` | Backfill hash and metadata identity fields after a successful match. |
| DELETE | `/api/books/:id` | Delete the metadata row. Local bytes are the client's business. |

### Decks and cards — `/api/decks`

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/decks` | Create a deck. Quota: 50 per user. |
| GET | `/api/decks/user/:userId` | List own decks. |
| GET | `/api/decks/user/:userId/cards` | Every deck with its full card list in one response. Feeds the star map, which needs all cards across all decks and would otherwise fan out per deck. Bounded by the card quota, so no paging. |
| GET | `/api/decks/:id` | One deck. |
| PUT | `/api/decks/:id` | Update a deck. |
| DELETE | `/api/decks/:id` | Delete a deck and its cards. |
| POST | `/api/decks/:id/cards` | Add a card. Quota: 5000 per deck. |
| GET | `/api/decks/:id/cards` | All cards in a deck. |
| GET | `/api/decks/:id/cards/due/count` | Just the count, for deck badges. |
| PUT | `/api/decks/cards/:cardId` | Update a card. |
| POST | `/api/decks/cards/:cardId/review` | Apply an FSRS outcome (`again`/`hard`/`good`/`easy`). **No-op if the card is not due** — no memory update, no `card_reviews` row, no `study_days` bump. |
| DELETE | `/api/decks/cards/:cardId` | Delete a card. |

### Study — `/api/study`

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/study/session` | Resolve a session's cards from a mode, size and optional deck list. Unowned deck IDs are silently dropped rather than erroring — no leak about which IDs exist. `limit` has a ceiling and `deckIds` a length cap plus per-entry UUID check. |
| GET | `/api/study/due/counts` | Total plus per-deck due counts in one request. Decks with nothing due are omitted from `byDeck`. |
| GET | `/api/study/prefs` | Card display prefs. Returns defaults when no row exists; the row is only created on first PUT. |
| PUT | `/api/study/prefs` | Upsert prefs. Both documents are JSONB; the schema bounds shape, key count and value types while staying open enough for new display toggles. |

### Stats — `/api/stats`

Read-only aggregations, scoped to `req.user.userId` in the repository.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/stats/activity` | Study activity over time, from `study_days`. |
| GET | `/api/stats/cards` | Card counts bucketed by state. |
| GET | `/api/stats/recent-upgrades` | Cards that recently climbed a rank. `?deckId=` narrows; validated in the route rather than left to the `::uuid` cast, which would surface a bad request as a 500. |

> **Removed 2026-08-17.** The `/api/devices` router (7 endpoints) was deleted along
> with `deviceService`, `deviceRepository`, `validation/devices.js` and the device
> quota. No client ever called it — none generated a `deviceId` or marked book
> availability. The `devices` and `book_availability` tables still exist in Postgres;
> dropping them is a separate, destructive migration that has not been written.

## Quotas

Enforced server-side with a `COUNT` before every insert. The web client mirrors these numbers to
disable buttons; that is presentation only.

| Resource | Limit |
|---|---|
| Books per user | 50 |
| Decks per user | 50 |
| Cards per deck | 5000 |

Text field caps live in `backend/src/config/limits.js` — every user-supplied column is Postgres
`text`, so these are the only bound.
